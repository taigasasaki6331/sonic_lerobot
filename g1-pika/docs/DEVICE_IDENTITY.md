# 左右PIKAの識別記録（2026-09-14）

ユーザー指定: 先に接続・撮影した一式が右手、追加した一式が左手。
udev/by-pathの追加前後比較による対応。撮影・シリアル通信・動作指令なしで確認。

| 機器 | 右手 | 左手 |
|---|---|---|
| D405 USBシリアル | EXAMPLE_DEVICE_SERIAL | 012345678901 |
| D405カラーの現在のnode | /dev/video8 | /dev/video16 |
| 魚眼USBシリアル | 01.00.00 | 01.00.00 |
| 魚眼の現在のcapture node | /dev/video10 | /dev/video18 |
| USBシリアルの現在のnode | /dev/ttyUSB0 | /dev/ttyUSB1 |

このPCでのID_PATH（共通接頭辞 `pci-0000:00:14.0-usb-0:`）:

| 機器 | 右手 | 左手 |
|---|---|---|
| D405 | 3.2:1.0 | 2.2:1.0 |
| 魚眼 | 3.1:1.0 | 2.3:1.0 |
| USBシリアル | 3.4:1.0 | 2.4:1.0 |

魚眼のシリアルは実際に重複。USBシリアル2台にもID_SERIAL_SHORTがない。
共通by-idリンクは今回左手を指しており、左右選択には使用不可。
左D405の012345678901はOSが実際に報告した値。製造時の個体固有番号かは未確認で、
一般的な個体一意性は保証しない。少なくとも現在の右D405とは異なる。

別PCではvideo/tty番号とby-pathを持ち越さず、左右を再対応付けする。
上記は識別記録のみで、実行コードの左右選択設定はまだ未実装。
既存camera-checkは同型機複数を拒否するため、両手接続状態での撮影には対応変更が必要。

## USB 2/3対応の追加確認

このPCのsysfsで `usb1-port2/peer → usb2-port2`、
`usb1-port3/peer → usb2-port3` を読み取り確認できた。
単にUSBバス番号やポート番号の一致を仮定せず、peer関係を利用する手掛かりがある。
ただし確認時点ではlsusb -tに左右PIKAがどちらも現れず、内蔵機器のみだった。
実ハブ配下からD405・魚眼・USBシリアルをまとめる自動識別は未実装・未検証。
別PCや外付けハブでも同じ情報が得られるとは未確認。内部ID取得処理の調査も未完了。
