# 実入力・送信なし統合

## 到達点

実入力を受ける処理・配置・終了手順を実装済み。**一時的な受信優先度RR/1で3秒の実入力・送信なし統合試験に合格**。
2026-09-24 run-b5do1ocs: ACT/IK93回・SONIC150回、入力2プロセスと4ワーカーが正常終了。
186画像/150身体窓の記録整合と、対象受信プロセスへの優先度適用・終了も確認。
魚眼はbuffer1で約15fps、buffer4で約30fps。露出変更は不要で元へ復元済み。
通常優先度では身体受信周期のばらつきで3秒試験が失敗している。一回の改善で根本原因を確定しない。
実機動作や長時間安定性の合格ではない。詳細PROGRESS.md。
身体/腕/グリッパの動作指令、制御権切替、リモコン操作は含まない。
通常のG1Deployを起動せず、推論専用C++ワーカーでSONICを実行する。

- G1: 既存の受信専用DDS subscriber → 10フレーム身体履歴 → ZMQ :6159。
- G1: 右カメラ2台＋右PIKA幅＋身体snapshot → ZMQ :6158。
- galleria: 30Hz ACT/IKの絶対参照、50Hzの最新身体履歴からSONIC観測を再生成 → ファイル記録のみ。
- tiger: 配置/ログ回収。センサー通信を中継しない。

ACT、IK、観測生成、SONICは別ワーカー。初期化・ACTウォームアップ後に初めてG1入力を開く。
h1相対actionはIKで一度だけ絶対参照へ変換し、50Hz側で重複積算しない。
PIKA幅は別欄で保持し、Dex3へ変換/グリッパへ送信しない。

## 実行境界

2026-09-24のカメラ・身体・右シリアル読み取りは了承済みで試験を実施した。
別の運用者・別の試験では読み取り範囲を確認してから実行する。
シリアルopenにはMCU resetの可能性がある。動作指令の承認とは別。

```bash
make online-record DEVICE_READ_ACK=1
```

上記は自動sudo/優先度変更をしない。今回のRR/1はユーザーが別端末で起動した90秒限定の補助による。
`scripts/temporary_receiver_priority.py`は専用path/argv/所有者/バイナリhashを照合した新規receive_state最大2つだけを対象にする。
終了時に通常優先度へ復元するか対象プロセスの終了を確認し、記録を残す。恒久権限追加はしない。
補助は現在終了済みであり、次回も同じ優先度条件が自動適用されるわけではない。

既定は1秒、ACT/IK33回・SONIC50回。`config/online-record.json`で整数1〜30秒のみ指定可能。
撮影が制御計算より先に始まるため、終了余裕として新規policy入力を3件追加取得する。
30秒では903/1500回。最後の参照の鮮度条件を延ばす仕組みではない。
`DEVICE_READ_ACK`なしではSSH前に停止する。`hardware_output_enabled=true`は設定拒否。
モデル/ビルド/SSH設定は`config/development.json`、G1/デバイスは`assets/network/g1-runtime-access.json`。
入力専用の有線IP/ポートは固定値との一致を検査し、Wi-Fiへの迂回や未知host keyの受入れはしない。
既存galleria環境を利用。新規OS・ドライバ・サービスのインストールはしない。

G1では新しい一時フォルダに受信ソース/入力スクリプトを配置し、既存CycloneDDS 0.10.2でコンパイルする。
身体受信のDDSはrt/lowstateのみ。PC間の画像/身体伝送はZMQのまま。
ZMQのIP制限は認証/暗号化の代替ではなく、信頼された隔離LANを前提とする。

## 入力/終了の判定

身体履歴は実測10件、20ms±2ms、有限値、uint32 tickの前進を必須とする。
連続窓で重なる9件の不一致、重複/欠落、古い参照、遅い推論は停止扱い。
不足履歴を複製したり、保存データに切り替えて継続したりしない。
実測姿勢が更新されるたびにencoderの相対姿勢とdecoderの身体観測を再計算する。
過去actionは直前の**計算出力**を保持するが、身体がそれを実行したという意味ではない。

鮮度はG1内で測った受信年齢＋galleria内の要求往復時間による保守的上限。
カメラは処理後の年齢を報告するため、RTTから重複するG1実測処理時間だけを控除する。
実測処理時間がRTTを超える場合は拒否。画像取得はACT/IKと並行、待機キューも鮮度に含む。
異なるPCのmonotonic時計同士を引かない。カメラの露光同期や真の取得遅延の検証は別途必要。
診断の100ms鮮度/20ms計算期限は未調整の開発条件で、物理的安全基準ではない。
身体サンプルの20ms±2msとGPUスケジューラの時刻は別々に検査する。
GPU側は時刻逆行/40ms以上の停止を拒否し、20ms±2msを外れた実行間隔は報告に残す。
これはリアルタイム保証ではない。身体側の連続窓・重複・欠落チェックは緩めていない。
実機初回で条件不成立なら理由とログを残し、閾値を自動緩和しない。

通常は全source/workerへ停止要求し、終了コードを確認。
G1の各SSHジョブは最大90秒＋強制終了猶予3秒。受信Cプログラム自体も60秒で終了する。
GPU側ジョブは240秒＋猶予3秒、tiger側SSHは270秒、結果回収30秒で打ち切る。
SSHを切っただけでは遠隔終了を確認した扱いにしない。
異常終了時も今回の一時フォルダに一致する同一ユーザーの入力プロセスだけをTERMし、残存を確認する。
確認失敗はreport.source_cleanupへ残し、合格にしない。これは実機の非常停止ではない。

## 記録と再現

新しい`artifacts/full-record/run-*/`に設定、配置先、GPUログ、`outputs/report.json`を保存。
実入力実行では各画像のJPEG/hash、画像時点の身体履歴・幅、各50Hz周期の身体履歴/推論結果を保存する。
JPEGは内容hash名で保存し、同一内容を重複保存しない。既存hashの内容不一致はエラーにする。
`capture-NNNN.json`/`body-NNNN.json`に入力を保存し、reportからファイル名とhashで参照する。
全身体窓を制御プロセスのheapに保持し続けないことで、記録によるGC停止を抑える。
取得失敗でも部分結果を残す。既存ログ・学習データ・モデルは上書きしない。
画像一括回収より先にreport/workerログを回収する。一括回収の失敗も非ゼロ終了で明示する。
一括回収はtar.gzにまとめ、展開時にパス逸脱・リンク・重複名・容量・既存内容の相違を拒否する。
現段階の記録は評価用であり、自動で学習データに登録しない。

G1なしで同じ処理を検査:

```bash
make check-offline
make check-runtime
make online-fixture-check RATE_SECONDS=30
make measured-record-check STATE=artifacts/sonic-state/sonic-state-McdQQD/state.jsonl
python3 -I scripts/verify_online_record.py --report artifacts/full-record/run-u1cqm5a6/outputs/report.json
```

`online-fixture-check`は実モデル4つを使うが、入力は保存画像/身体snapshotの反復と人工時刻。
実センサー・物理エンジンは使わない。実測同期データや実機での周期性能と混同しない。
`measured-record-check`は別日の実身体記録だけを使い、画像/LeRobotを混ぜない。
379区間で持続処理と既存バッチの関節出力差0を確認:
`artifacts/full-record/run-zr2081r6/outputs/report.json`。
履歴の重なり/tick検査追加後も`artifacts/full-record/run-x2w0eq6u/outputs/report.json`で一致。
観測の回転計算の最大差8.95e-18、身体観測差0。float32精度範囲で比較している。
人工入力30秒＋入力記録の検証は`run-u1cqm5a6`。900 policy/1500 control、4 worker exit 0。
host実行間隔15.387〜25.157ms、20ms±2ms外れ2件。GC最大約0.758ms。実時間保証ではない。
`verify_online_record.py`は画像/入力JSONのhash、連番、窓の重なり、幅経路を検査する。
この検査もファイル整合性の確認であり、入力が実機由来かどうかや物理的安全性の独立認証ではない。
