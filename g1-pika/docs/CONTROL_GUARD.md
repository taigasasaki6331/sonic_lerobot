## 実行

```bash
make check-guarded-wbc
make guarded-wbc-view
```

前者は単体試験、通常WBC、5種類の異常注入、教師軌道、記録画像を使った
固定LeRobot ACTの206フレーム実推論→非同期目標→WBC→記録境界を一括検査する。
既存のローカル学習済みモデルとデータセットが必要。再学習はしない。
各実行を `artifacts/guarded-runtime/run-*/` に分け、summary.json、ログ、
50Hzの承認済み関節目標を保存する。異常ケースの子プロセス終了コード1は
期待する理由・100件で記録停止を確認した場合のみ検査成功と扱う。
後者は12秒のPIKA付きWBC表示。カメラポリシーではなく規定軌道を動かす。

## 実機安全性との境界

これは抽象関節目標の**ローカル記録**であり、Unitree LowCmdではない。
関節順序はMuJoCoモデル由来で、実機のモーター番号対応やmode/CRCは未実装。
50Hz記録のtauは重力補償のスナップショット。200HzのMuJoCo PDトルク全送信を
記録・検査するものではなく、最初の制御tickまでの初期PDもこの境界の対象外。

異常時は不正目標を適用せず**シミュレーションを終了**する。
実機で送信を止めれば安全に立位停止できるという意味ではない。
検査はシミュレーション時計であり、本番のwall-clock期限・停止遅延を証明しない。
所有者検査もプロセス内の協調規約で、他のDDS送信者を排除する仕組みではない。
速度・トルク・ゲイン上限、追従誤差、姿勢、衝突、実測状態の物理妥当性を
網羅した実機安全制限ではない。関節範囲と0.1秒閾値は実機承認値ではない。

次の本番向け作業は、実測状態→WBC入力の対応と基準座標、実測幅、制御所有権の
取得/返却、機体仕様に合った停止遷移の確定。実機指令禁止を解除しないまま
記録専用経路で準備し、動作試験は別途承認と安全条件が必要。
