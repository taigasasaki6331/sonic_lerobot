# PIKA把持力測定の準備

2026-10-01最新のユーザー訂正：目的は測定ではなく、簡単に力を変えて動作を試すこと。
測定器の準備を進行条件にしない。現在の操作は
`control_pika_gripper.py interactive` の `grip 0.2` / `current 0.4` / `open 0.6`。
PIKA_GRIPPER_CONTROL.mdを参照。以下の測定計画は以前の解釈に基づく参考記録として保存する。

ユーザーは「どれくらいまで力を出せるか」を検証したい。
2026-10-01にユーザーが「測定器はまだない」と回答。実機試験は行っていない。
以下は測定計画であり、実機の自動スイープ起動コマンドではない。

## 測定器がない現在の進め方

最大把持力Nの確定には圧縮対応のフォースゲージ/ロードセルが必要。
現時点で可能なのは、重さが分かる物体を保持できるかによる保持可能重量の評価。
摩擦/表面/物体形状/開口幅の条件を合わせ、低い位置で落下を受ける構成にする。
保持可能重量を把持力Nへ直接換算しない。吊り下げG1の腕や身体をこの試験のために駆動しない。
コード準備として2 A超過を拒否する処理は完了。
力Nの読取り実装・実測最大値は、測定器がないため現時点では提供できない。

## 測る量

圧縮ロードセルまたは圧縮対応フォースゲージを指の間へ固定し、
挟む方向の反力をN単位で測る。同じ開口幅・接触点・接触材・電源条件を維持する。
片側の反力・両側の力の和など、把持力の定義を記録して比較する。
ばねばかりや重りを引き抜く試験では滑りの摩擦を含む保持性能を測るため、
圧縮把持力と同じ測定値として扱わない。

電流設定からは実際の力Nを直接取得できない。
ktは対象軸のトルク換算定数であり、指先の力には機構形状/開口幅/接触点が関係する。
未確認のktを調整して「実測N」の代用にしない。

## 範囲の根拠

[AgileX公式SDK](https://github.com/agilexrobotics/pika_sdk/blob/master/pika/gripper.py)の
`set_motor_torque()` は電流単位A、範囲0〜2 Aと記載する。
control_pika_gripper.pyは現時点で `0 < A <= 2` を送信前に検査する。
その上限は連続拘束運転の保証や、必ずその値まで試験する指示ではない。
上限設定の読み戻し/ACKもなく、設定電流と実際のmotor.Currentを別々に記録する。

[メーカー製品資料](https://static.generation-robots.com/media/agilex-pika-brochure.pdf)の
PIKA Gripper表には最大力を「2kg」と記載する。kgfを意味するなら約19.6 Nだが、
この表だけでは力の定義・測定幅・保持時間が分からない。
資料値を現在の実機で保証された測定値や、既知のktと扱わない。

## 測定器を確認してから具体化する試験

1. センサーの許容荷重・圧縮測定への対応・取り付け方法を確認する。
   実験中の力停止値はセンサー/治具の定格以内に設定する。
2. ゼロ点を確認し、低い電流設定から短時間の接触保持を行う。
3. 一段ずつ電流を変更して実測N、実電流の生値、角度、温度、保持時間を記録する。
   上限電流・測定器の荷重上限・温度/異常状態・人の中断で終了する。
4. 各段の負荷を解除してから次の段へ進め、同条件で繰り返し測定する。
5. 得られた「指定電流 vs 実測力」と、試験条件下の最大確認値を報告する。
   発熱/連続保持・別の開口幅の結果を同一条件の最大値として一般化しない。

指/手で力を測らない。センサーや治具を保持し、人が指先の間へ手を入れない構成にする。
具体的な電流刻み/保持秒数/力上限/温度上限は測定器・実機の条件を確認して決める。
2 Aまでを自動的に増やす試験はまだ提供しない。

## 現コードの限界と次の実装

`close` / `move` は角度到達を確認する一般操作。
センサーを挟むと目標角度へ届かず、正常な接触でも未到達として無効化/終了する。
把持力試験には接触時の扱い・期限付き保持・測定器値の記録を別途追加する必要がある。
既存の到達期限を長くして拘束運転することを測定用の実装とは扱わない。
測定器の型番/読取方法（目視/USB/シリアル等）を確認してから、
その測定方法に対応する操作と終了条件を具体化する。

準備段階の検証: 23件の単体試験成功。2 A超過やNm→A換算超過は送信なしで拒否。
実機の力、kt、2 A設定の受理/連続保持はいずれも未検証。
