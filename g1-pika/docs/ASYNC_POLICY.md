# 推論待ちをしないWBCシミュレーション

2026-09-14。USB左右識別は本番PCでの接続時に延期し、非同期経路を追加した。

```sh
make policy-async-view
```

画面なしは `make policy-async`。カメラ・G1接続は不要。
既存のローカルACTチェックポイントと記録画像を使用し、30フレームを実推論する。

## 実装

- 推論は既存の別Pythonプロセス。WBC側は非ブロッキングpipeで要求送信・応答確認する。
  制御コールバック内で推論待ち、sleep、スレッドjoinをしない。
- 未完了要求は最大1件。応答待ちは直前のTCP目標を保持し、WBC計算を継続する。
  応答を1回だけ適用し、sequence・記録時刻・action検査は既存境界を再利用。
- monotonic時計で要求後0.5秒を超えたら拒否をラッチ。遅れて届いた応答は適用しない。
  この0.5秒は試験用の値であり、実機で許容できる停止時間ではない。
- GUIなしでも物理ステップを壁時計に合わせて待機し、待ち時間中のWBC継続を試験する。
  推論プロセスの初期化待ちと終了処理は制御ループ外。

## 検証範囲

通常runで30/30指令、12秒の立位・追従検査合格。
推論要求応答p95約149 msに対し、bridgeコールバックp95約0.14 ms、最大約1.32 ms。
WBC計算p95約6.57 ms。待機中も148回の目標保持コールバックを実行。
旧同期runのWBC p95約104 msとはフレーム数・実行条件が異なるため、厳密な性能比較ではない。

`make check-policy-async` は疑似時計で応答待ち継続、期限切れ後の遅着拒否、
stale拒否、後処理を検証する。既存bridge/actionのテストも維持。

追加のシミュレーション異常注入は `--policy-fault delay`（6番目の応答配送を250 ms保留）、
`--policy-fault silence`（6番目の応答を配送しない）。推論worker自体を停止する注入ではない。
silenceは期限切れのため終了コード1になるのが期待結果。
実行結果: delayは30/30指令で合格、silenceは5指令後に期限切れとなり、
いずれも12秒の立位維持を確認。全3runのMuJoCo警告は0。
スナップショットは `docs/async-policy-2026-09-14.json`。
ログは `artifacts/policy-sim[-delay|-silence]-async-latest.json` と対応events。

**これは実時間制御の完成ではない。** CPU推論は30 Hz未達で、記録フレームを
応答速度に合わせて順に再生している。元データと同じ動作速度ではなく、画像閉ループでもない。
0.5秒の検査対象は要求応答の経過時間で、実カメラ観測の鮮度・姿勢同期は未検証。
OSスケジューリング・WBCの実時間周期保証・低レベル通信断対策は本番環境で別途必要。
グリッパは固定、実機送信なし、学習済みモデルの実機採用は未承認。
