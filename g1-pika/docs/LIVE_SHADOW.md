## 経路と制約

G1カメラ → SSH → 開発PC → SSH → galleria ACT → 開発PCの結果ログ。
G1へ送るアプリケーションデータはカメラ要求seqとstopのみ。推論actionをG1へ返す経路はない。
SSH秘密鍵の転送・公開サーバーの起動は行わない。

G1では右D405をシリアル指定し、魚眼はDECXINが1台の場合のみ選択。
カメラごとに継続readerを持ち最新1枚を保持。要求時にJPEG品質90で640x480画像を転送。
開発PCでは未完了要求を1件に制限し、最大5組/秒を要求する診断設定。
重複seq/counter、古いread、欠損、読取/送信timeoutは失敗として終了し、ログへ残す。
GPUではJPEGをRGB復号して、学習時と共通のrgb_inputで128x96へ縮小する。
同じ画像の繰り返しではなく新しいフレームを入力したが、JPEGによる学習画像との差は未評価。

現在は両PCともWi-Fi経路。有線直結の本番構成・30 Hz達成ではない。
グリッパ幅は仮値4cm、TCP stateはidentity契約。実測グリッパ・G1状態は未入力。
このpassedは撮影から推論記録までの疎通であり、action品質・安全性・自律タスク成功ではない。
